# Evidence and Product-Specific Actions

## Analyze before proposing

Create a compact product-use analysis:

- visible identity, silhouette, supported surfaces, controls, attachments, packaging, and material boundaries;
- confirmed functions, effects, use states, and sensory descriptions;
- ambiguous controls, hidden mechanisms, unsupported angles, and unsafe operations;
- visible results that can demonstrate each fact without inventing a mechanism.

Product resemblance and category convention are not evidence. Infer candidate actions, not facts.

## Route each fact

Use one primary route per fact-action mapping:

1. `mechanism_led`: exact control location and operation method are visible or explicitly confirmed. Precise operation is allowed.
2. `state_led`: intended product/body/environment state is confirmed and does not depend on an unknown control.
3. `effect_led`: function or result is confirmed but control or sequence is unknown. Show the operating state or a modest proxy without touching a guessed control.
4. `appearance_led`: only visible design, scale, texture, finish, or color is confirmed.

Decision order:

```text
Exact control and operation confirmed?
  yes -> mechanism_led
  no  -> intended state confirmed without it?
           yes -> state_led
           no  -> function/result confirmed?
                    yes -> effect_led
                    no  -> appearance_led or request confirmation
```

An effect proxy must be modest and directly related to the confirmed function. Do not convert visible movement, a reaction, or a status change into a numeric or superiority claim.

## Propose real alternatives

Each option must change the proof strategy, not just the camera angle. Include its four-stage arc, hero action, evidence basis, omitted unknowns, and tradeoff.

If only one route is safe, present one route and the rejected alternatives. Do not invent weak choices.

## Build the demonstration ledger

Map each selected fact to:

- source and confirmation status;
- evidence route;
- physical action;
- observable response;
- required view;
- safe spoken wording;
- prohibited implication;
- target stage;
- operation confidence;
- whether a precise control action is allowed.

Require at least three distinct action families across four stages. Repeated holding, pointing, camera pushes, and close inspection count as one family. Every stage must change the product state, body-product relationship, product-environment relationship, or observable effect.

## Select the hero action

Choose one supported action that identifies how the product is used or what visible attribute matters. Placement is a hero result only for a confirmed display-oriented product or an explicitly approved packaging-only story. A usable product needs a real state, effect, operation, or result.
